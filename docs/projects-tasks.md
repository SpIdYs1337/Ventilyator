# Проекты и задачи

## Обновление существующей установки

Все команды выполняются на Ubuntu-сервере, в существующем checkout. `.env`, адрес браузера, пользователи, пароли и DATA_ROOT сохраняются. Повторять bootstrap администратора и configure.py не нужно.

Перед обновлением сохраните дамп PostgreSQL (содержит закрытые данные). Это резервная копия базы, а не полная процедура восстановления всей платформы:

```bash
cd /opt/ventilyator
mkdir -p .local/backups
(
  set -eu
  umask 077
  vnt_dump=".local/backups/before-projects-$(date -u +%Y%m%dT%H%M%SZ).dump"
  docker compose exec -T ventilyator-postgres pg_dump -U ventilyator -d ventilyator -Fc > "$vnt_dump"
  test -s "$vnt_dump"
)
git pull --ff-only origin main
docker compose build ventilyator-api ventilyator-web
docker compose stop ventilyator-api ventilyator-worker
docker compose run --rm -T ventilyator-migrate
docker compose up -d --no-build --wait --wait-timeout 180
docker compose ps -a
```

При ошибке миграции остановитесь и изучите сообщение; не запускайте reset/db push и не удаляйте данные. Новая миграция добавляет таблицы и разрешения существующим стандартным ролям. Она не пересоздаёт пользователей. `ventilyator-migrate` после успешного выполнения показывает `Exited (0)`.

После обновления перезагрузите страницу браузера. Если вкладка долго оставалась открыта, выполните Ctrl+F5. Адрес остаётся прежним, включая HTTP LAN, если вы его выбрали ранее.

## Первый рабочий проект

1. Войдите администратором, откройте «Проекты» и нажмите «Создать проект».
2. Укажите название и ключ из 2–12 латинских букв/цифр, начиная с буквы, например VNT. Ключ становится частью номера задачи VNT-1 и впоследствии не меняется.
3. Откройте проект → «Участники». Найдите ранее созданного локального сотрудника, выберите роль и добавьте его.
4. В «Задачах» создайте задачу, укажите описание, тип, приоритет, исполнителя и срок. Исполнителем может быть активный участник с правом изменения задач.
5. Откройте карточку задачи, измените её статус, добавьте комментарий и посмотрите историю изменений.
6. Войдите под сотрудником: он увидит только доступные проекты. Фильтр «Назначенные мне» покажет его задачи.

## Права

Создание проектов требует `projects:create` или `projects:manage`. Стандартные System Administrator и Organization Administrator получают оба разрешения при миграции; Department Manager и Project Administrator — только создание. Существующие Team Member, Viewer и Guest не получают глобальных проектных разрешений.

Владелец проекта управляет его настройками и участниками; удалить или понизить владельца нельзя. В проекте доступны роли:

| Роль | Возможности |
|---|---|
| Администратор проекта | Настройки, архивирование, участники, задачи и комментарии |
| Участник | Чтение, создание/изменение задач, комментарии |
| Наблюдатель | Только чтение проекта, задач, комментариев и истории |

`projects:manage` явно даёт управление всеми проектами **своей** организации. Само наличие `users:manage` или `system:read` этого не даёт. Другие организации недоступны даже проектному администратору. Сервер проверяет права для каждого действия, независимо от видимости кнопки.

При удалении участника из проекта его задачи сохраняются, назначения снимаются и записываются в историю. Участник теряет доступ; его комментарии и авторство сохраняются. При понижении до наблюдателя назначения также снимаются. В архиве проект доступен только для чтения, администратор может восстановить его в настройках.

## Поведение и ограничения этого этапа

Шесть стандартных статусов: новая, запланирована, в работе, на проверке, выполнена, закрыта. Сейчас участникам разрешены переходы между любыми стандартными статусами. При выполнении фиксируется время завершения, при повторном открытии оно очищается. Настраиваемый движок процессов ещё предстоит реализовать.

Доска поддерживает перетаскивание на компьютере; на мобильном устройстве статус можно выбрать в карточке. Доска и список показывают одну страницу до 50 задач, доступна пагинация. Поиск проверяет название и описание, фильтры — статус и текущего исполнителя. Это текстовый поиск, не глобальный полнотекстовый индекс платформы.

Другие сотрудники видят изменения при опросе каждые 10 секунд. WebSocket пока не используется. Сохранение устаревшей версии возвращает 409 и не перезаписывает новые данные. Скопируйте свой текст, обновите карточку и повторите правку.

Описания и комментарии пока обычный текст, React экранирует HTML. Вложения, редактор документов, зависимости и иерархия подзадач, учёт времени, массовые операции, произвольные workflow, Scrum/Gantt, SMTP и IMAP-панель не входят в этот промежуточный этап. Выбор типа «Подзадача» пока задаёт только тип, не связь с родительской задачей. Необратимое удаление проекта/задач намеренно ещё не добавлено; для проектов доступен архив.
