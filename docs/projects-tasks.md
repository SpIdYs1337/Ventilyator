# Проекты и задачи

## Обновление существующей установки

Все команды выполняются на Ubuntu-сервере, в существующем checkout. `.env`, адрес браузера, пользователи, пароли и DATA_ROOT сохраняются. Повторять bootstrap администратора и configure.py не нужно.

Инструкция и скрипт обновления теперь включают согласованный backup базы и файлов:

```bash
cd /opt/ventilyator
git pull --ff-only origin main
bash infrastructure/scripts/deploy.sh
```

Подробности — [DEPLOYMENT.md](../DEPLOYMENT.md). При ошибке миграции не запускайте reset/db push и не удаляйте данные. Миграции сохраняют пользователей и существующие статусы задач; migrate после успеха показывает Exited (0).

После обновления перезагрузите страницу браузера. Если вкладка долго оставалась открыта, выполните Ctrl+F5. Адрес остаётся прежним, включая HTTP LAN, если вы его выбрали ранее.

## Первый рабочий проект

1. Войдите администратором, откройте «Проекты» и нажмите «Создать проект».
2. Укажите название и ключ из 2–12 латинских букв/цифр, начиная с буквы, например VNT. Ключ становится частью номера задачи VNT-1 и впоследствии не меняется.
3. Откройте проект → «Участники». Найдите ранее созданного локального сотрудника, выберите роль и добавьте его.
4. В «Задачах» создайте задачу, укажите описание, тип, приоритет, исполнителя и срок. Исполнителем может быть активный участник с правом изменения задач.
5. Откройте карточку задачи, измените её статус, добавьте комментарий и посмотрите историю изменений.
6. Войдите под сотрудником: он увидит только доступные проекты. Фильтр «Назначенные мне» покажет его задачи.

## Права

Создание проектов требует `projects:create` или `projects:manage`. Стандартные System Administrator и Organization Administrator получают оба разрешения при миграции; Department Manager и Project Administrator — только создание. Существующие Team Member, Viewer и Guest не получают глобальных проектных разрешений.

Владелец проекта управляет его настройками и участниками; удалить или понизить владельца нельзя. В проекте доступны роли:

| Роль | Возможности |
|---|---|
| Администратор проекта | Настройки, архивирование, участники, задачи и комментарии |
| Участник | Чтение, создание/изменение задач, комментарии |
| Наблюдатель | Только чтение проекта, задач, комментариев и истории |

`projects:manage` явно даёт управление всеми проектами **своей** организации. Само наличие `users:manage` или `system:read` этого не даёт. Другие организации недоступны даже проектному администратору. Сервер проверяет права для каждого действия, независимо от видимости кнопки.

При удалении участника из проекта его задачи сохраняются, назначения снимаются и записываются в историю. Участник теряет доступ; его комментарии и авторство сохраняются. При понижении до наблюдателя назначения также снимаются. В архиве проект доступен только для чтения, администратор может восстановить его в настройках.

## Задачи, процесс и планирование

Стандартные статусы остаются исходным процессом. Вкладка «Процесс» позволяет менеджеру задать собственные статусы, завершающие состояния, WIP-лимиты и разрешённые переходы с признаком «только администратор». Сервер проверяет процесс и лимиты по всем задачам проекта; занятый статус нельзя просто удалить или изменить его смысл завершения. На мобильном устройстве статус выбирается в карточке, на desktop доступно перетаскивание.

У задачи доступны даты начала/срока, метки, оценка в минутах и story points, чек-лист, настоящие связанные подзадачи, блокирующие зависимости, наблюдение, ручной учёт времени и постоянный таймер. Циклы зависимостей и дерева запрещены; незавершённая блокирующая задача не позволяет завершить зависимую. Таймер один на сотрудника, сохраняется при перезагрузке; отзыв прав записи завершает его с записью времени. Копирование задачи не копирует автоматически все вложения/обсуждения/связи.

В «Спринтах» создайте план, перенесите задачи из backlog, запустите спринт. Одновременно активен один на проект. Закрытие сохраняет результат и возвращает незавершённое в backlog. «Временная шкала» отображает даты, «Отчёты» — реальные статусы/исполнителей/учтённое время; это ещё не полный Scrum burndown/velocity или редактируемый Gantt.

«Вложения» хранят файлы локально с ACL, версиями и корзиной. «Связанные документы» показывают доступные страницы; задача может быть создана прямо из базы знаний. Описания/комментарии задач — безопасный обычный текст, документы — Rich JSON/Tiptap.

Список/доска отображают страницу задач с пагинацией; WIP при этом считается по полной базе. Изменения опрашиваются каждые 10 секунд, WebSocket пока нет. Сохранение устаревшей версии возвращает409; сохраните свой текст и повторите на новой версии. Полнотекстовый поиск платформы работает по доступным задачам/страницам/проектам. Детальная часть отчёта ограничена 10000 задач, интерфейс показывает предупреждение об усечении.

Массовые операции, произвольные поля, релизы, автоматизация и полный язык запросов остаются в [ROADMAP.md](../ROADMAP.md).
