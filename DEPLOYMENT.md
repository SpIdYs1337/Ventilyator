# Развёртывание и обновление Ventilyator

Команды выполняются на Ubuntu-сервере. На компьютере пользователя нужен только браузер. Для первой установки Docker, GitHub checkout, конфигурации и администратора используйте [INSTALLATION.md](INSTALLATION.md).

## Существующая установка с созданным администратором

```bash
cd /opt/ventilyator
git status --short
git pull --ff-only origin main
bash infrastructure/scripts/deploy.sh
docker compose ps -a
```

Если checkout расположен иначе, замените только первую строку. `git pull --ff-only` останавливается при конфликтующих локальных изменениях; не заменяйте его сбросом файлов. Скрипт:

1. Проверяет существующий `.env`, собирает API/worker, web и proxy.
2. Проверяет PostgreSQL/Redis и создаёт полную копию `.local/backups/ventilyator-*`, если в БД уже есть пользователи. На время копии API/worker приостанавливаются.
3. Останавливает писателей, запускает `prisma migrate deploy`, запускает сервисы и ждёт healthchecks.

После успешного запуска API, worker, PostgreSQL, Redis и web должны быть `healthy`, proxy — работающим, migrate — `Exited (0)`. Откройте **прежний адрес** сервера и обновите страницу; при старой вкладке используйте Ctrl+F5. Администратор и существующие данные сохраняются. Не запускайте заново `configure.py`, bootstrap и не удаляйте DATA_ROOT.

Резервная копия содержит секреты. Перенесите её на защищённый резервный носитель; описание — [BACKUP_RESTORE.md](BACKUP_RESTORE.md). Для сборки и копии нужно свободное место: проверяйте `df -h` перед обновлением.

## Доступ по IP в изолированной локальной сети

Если этот режим уже настроен, пропустите переключение. Для новой установки или перехода с другого режима, **после создания `.env`**, замените IP адресом Ubuntu-сервера:

```bash
cd /opt/ventilyator
ip -br address
python3 infrastructure/scripts/configure-lan.py 192.168.1.50
docker compose up -d --no-build --wait --wait-timeout 180
```

Откройте `http://192.168.1.50` в браузере. DNS, hosts и установка клиентского приложения не требуются. Для другого порта: `configure-lan.py 192.168.1.50 --port 8080`, адрес `http://192.168.1.50:8080`. HTTP-режим предназначен для изолированной тестовой сети; HTTPS с корпоративным сертификатом описан в INSTALLATION.md. Настройка LAN не заменяет пересборку после изменения исходников.

## Что настроить через браузер

1. «Администрирование → Пользователи»: создайте локальных сотрудников и назначьте роли. «Роли»: настройте собственные наборы разрешений.
2. «Проекты и задачи»: создайте проект, добавьте участников, создайте задачи. В проекте доступны процессы, спринты, временная шкала и отчёты.
3. «База знаний»: создайте пространство, добавьте участников, создайте и опубликуйте страницу. Черновик до публикации не становится общей страницей.
4. В задаче/странице прикрепляйте файлы. Права проверяются и при скачивании; серверные пути пользователи не задают.
5. «Администрирование → Почта»: при необходимости настройте SMTP, сохраните, проверьте соединение и отправьте тестовое письмо себе. Каждый сотрудник включает email в «Уведомлениях». Без SMTP внутренние уведомления работают.
6. Там же включите IMAP при необходимости. Для существующего локального сотрудника явно разрешите IMAP в его карточке. Локальный пароль продолжает работать независимо от почты. Автосоздание допустимо только с непривилегированной ролью.
7. «Администрирование → Хранилище»: проверьте квоту и незавершённые загрузки. «Мои устройства»: смените собственный пароль и проверьте активные сессии.

SMTP/IMAP-пароли не задаются в публичной GitHub-конфигурации. Для собственного CA и антивируса см. [CONFIGURATION.md](CONFIGURATION.md).

## Проверка и диагностика

```bash
cd /opt/ventilyator
docker compose ps -a
docker compose logs --tail=100 ventilyator-migrate
docker compose logs --tail=100 ventilyator-api ventilyator-worker
curl --fail --show-error http://192.168.1.50/api/health/ready
```

Последний адрес замените фактическим; для HTTPS используйте доверенный CA, без `-k`. При сбое миграции скрипт прекращает обновление и оставляет API/worker остановленными. Сохраните ошибку, проверьте копию; не используйте `db push`, `migrate reset` и удаление данных. После устранения причины повторите `deploy.sh`. При неудачной сборке работающая установка продолжает использовать старые контейнеры.

## Границы этой версии

Проверен полный запуск Compose в облачной Linux-среде, API и desktop/mobile Chromium. Приёмка на отдельной чистой Ubuntu, с вашим корпоративным CA и почтовым сервером, ещё требуется. Полного паритета Jira/Confluence эта версия не заявляет; оставшиеся функции перечислены в ROADMAP.md.
