# Эксплуатация

Обновление существующей установки — [DEPLOYMENT.md](DEPLOYMENT.md), первая установка — [INSTALLATION.md](INSTALLATION.md). Существующие `.env`, DATA_ROOT и аккаунты сохраняйте.

```bash
cd /opt/ventilyator
docker compose ps -a
docker compose logs --tail=100 ventilyator-api ventilyator-worker
docker compose up -d --no-build --wait --wait-timeout 180
```

Перезапуск: `docker compose restart`. Миграция `Exited (0)` нормальна. Автозапуск обеспечивается Docker и restart:unless-stopped; вручную остановленный контейнер запустите через up. Не удаляйте данные, не используйте down -v/reset и не меняйте только пароль PostgreSQL в `.env` у уже инициализированной БД.

## Обновление и резервирование

```bash
git pull --ff-only origin main
bash infrastructure/scripts/deploy.sh
```

Скрипт собирает, делает согласованную копию, останавливает писателей, применяет миграцию и ждёт готовности. При неуспехе миграции оставляет API/worker остановленными. Откат образа не отменяет изменение схемы. Проверенное восстановление выполняется в отдельную пустую установку по BACKUP_RESTORE.md.

Следите за свободным местом/inode DATA_ROOT и Docker builder. Храните копии отдельно, проверяйте восстановление. Корзина учитывается в квоте, окончательная автоматическая очистка ещё отсутствует. Незавершённые upload можно сверить в панели хранилища; опубликованные байты вручную не удаляйте. Секретный ключ storage/.keys/mail.key храните вместе с backup.

## Диагностика

| Состояние | Проверка |
|---|---|
| Миграция nonzero | Лог ventilyator-migrate, соединение PostgreSQL, совместимость версии; не пропускать миграцию |
| API не запускается | Обязательные переменные, HTTPS в production, права storage UID 1000 |
| Worker unhealthy | PostgreSQL/Redis; heartbeat обновляется каждые 5 секунд и истекает через 20 |
| POST 403 | APP_ORIGIN должен совпадать с реальным браузерным адресом/портом |
| Вход 429 | Лимит 12/email и 100/IP за 15 минут; дождаться истечения, не отключать защиту |
| SMTP FAILED/SKIPPED | Журнал почты, включение SMTP/email, доступ пользователя, CA и ключ SMTP |
| IMAP 401 | Разрешённый домен, TLS, явная привязка/автосоздание, непривилегированная роль |
| Upload 409/503 | Квота с версиями/корзиной/резервами, место на диске, сверка операций |
| Ошибка TLS | Правильное имя сервера, доверенная цепочка CA, без отключения проверки |
| Timeout сборки | Доступ builder к registry/Prisma, proxy/CA, повтор с сохранённым кешем |

`docker compose config` без --quiet содержит секреты; не публикуйте его. Логи и дампы перед передачей проверяйте на закрытые сведения. Настройки почты не должны попадать в пользовательские сообщения об ошибках.

## Мониторинг

HTTP `/api/health/live` и `/api/health/ready`: ожидается 200. Проверяйте с доверенным CA; три последовательных отказа readiness — повод для оповещения. Zabbix agent может контролировать CPU/RAM, диск/inode, Docker-сервисы; приложениям Docker socket не предоставляйте. Prometheus/Grafana dashboard, нагрузочная приёмка, автоматическая retention и расширенные метрики ещё не реализованы.
