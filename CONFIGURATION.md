# Конфигурация

`.env` читается Docker Compose, имеет режим 0600, исключён из Git/build context. `configure.py` генерирует случайные пароли PostgreSQL/Redis и отказывается перезаписывать файл. Для существующей установки сохраняйте `.env` и DATA_ROOT.

| Параметр | Назначение |
|---|---|
| APP_HOST / APP_ORIGIN | Имя Caddy и точный origin браузера, включая порт |
| NODE_ENV | production требует HTTPS; development — отдельная тестовая сеть |
| DATA_ROOT | Локальные данные, по умолчанию /srv/ventilyator |
| POSTGRES_PASSWORD / REDIS_PASSWORD | Локальные секреты; DATABASE_URL / REDIS_URL должны им соответствовать |
| HTTP_PORT / HTTPS_PORT | Публикуемые порты Caddy |
| TLS_CERT / TLS_KEY | internal либо пути сертификата/ключа внутри контейнера |
| SESSION_MAX_DAYS | Абсолютный предел сессии: 7–90 дней, по умолчанию 30 |
| COMPOSE_FILE | Выбранные Compose-профили; configure-lan.py сохраняет base:lan |
| MAIL_CA_FILE | Дополнительный PEM CA внутри API/worker для SMTP/IMAP |
| ANTIVIRUS_REQUIRED | true: запрет публикации файла без успешной проверки ClamAV |
| CLAMAV_HOST / CLAMAV_PORT | Адрес clamd INSTREAM, порт по умолчанию 3310 |

## SMTP и уведомления

Настраиваются в «Администрирование → Почта», разрешение `mail:manage`. Укажите host, порт, implicit TLS либо обязательный STARTTLS, отправителя и при необходимости SMTP username/password. Сохраните и проверьте соединение; тестовое письмо ставится в очередь только текущему администратору. Пустое поле пароля при повторном сохранении сохраняет прежний пароль. API возвращает признак наличия пароля, а не секрет.

Пароль хранится AES-256-GCM с привязкой к организации. Ключ — `DATA_ROOT/storage/.keys/mail.key` (0600), отдельно от PostgreSQL. API и worker должны видеть один storage. Потеря ключа делает сохранённый SMTP-пароль недоступным; восстановите ключ из защищённой копии либо заново задайте пароль. Не удаляйте `.keys` при очистке storage.

Внутренние уведомления работают без SMTP. Сотрудник включает email в «Уведомлениях». Outbox PostgreSQL и BullMQ обрабатываются worker; журнал показывает PENDING/SENDING/SENT/FAILED/SKIPPED. Попытки ограничены пятью, ошибки не содержат SMTP-пароля. При отключении SMTP/сотрудника/доступа отложенная доставка пропускается. События о сроке проверяются каждую минуту, письма — примерно каждые пять секунд. Редкий дубль возможен при падении между приёмом письма SMTP и записью SENT.

## IMAP

Веб-настройки задают один разрешённый домен организации, host/порт, включение и политику автосоздания. Используется implicit TLS (обычно 993), проверяется CA и имя сервера. STARTTLS и OAuth2 для IMAP пока отсутствуют. Пароль почты не сохраняется и не журналируется.

Совпадение email не связывает локальную учётную запись автоматически. Администратор явно разрешает IMAP в карточке сотрудника. Автосоздание новых пользователей необязательно и допускается только с ролью без административных/проектных разрешений; допустимо `knowledge:create`. Локальный вход независим от IMAP. Старые IMAP_HOST/PORT/DOMAIN/ORGANIZATION_ID из `.env` поддерживаются как fallback, только если у организации ещё нет веб-настроек.

## Корпоративный почтовый CA

На Ubuntu установите публичный CA в каталог storage, доступный API/worker. Например, при стандартном DATA_ROOT:

```bash
sudo install -d -o 1000 -g 1000 -m 0700 /srv/ventilyator/storage/.keys
sudo install -o 1000 -g 1000 -m 0644 /путь/к/corporate-mail-ca.pem /srv/ventilyator/storage/.keys/corporate-mail-ca.pem
nano .env
```

Задайте `MAIL_CA_FILE=/app/storage/.keys/corporate-mail-ca.pem`, затем `docker compose up -d --no-build --wait --wait-timeout 180`. Используйте настоящий публичный CA, не приватный ключ. TLS-проверки не отключайте. Без MAIL_CA_FILE используется системное доверие Node/OpenSSL.

## Опциональная антивирусная проверка

Укажите CLAMAV_HOST, CLAMAV_PORT и ANTIVIRUS_REQUIRED=true в `.env`; адрес должен быть доступен API по Docker-сети. Управление самим clamd и обновлением баз остаётся задачей администратора. Публикация завершается только после чистого ответа; заражение или недоступность сканера в обязательном режиме завершают загрузку ошибкой. При заданном host проверка также выполняется без обязательного режима; без host и с false она выключена. Проверен протокол на локальном имитаторе clamd, настоящий экземпляр с актуальной базой ещё требует приёмки.

## Сборка и сеть

Нужны registry.npmjs.org, Docker Hub/CDN, binaries.prisma.sh и подписанные Debian-репозитории. Корпоративный build secret `corporate_ca` и обычные proxy build args поддерживаются Dockerfile. Не отключайте TLS/integrity/Prisma checksum. Приложению при обычной работе интернет не нужен; только включённые SMTP/IMAP обращаются к настроенным администратором серверам.
