# Резервное копирование и восстановление

Реализована согласованная копия PostgreSQL и локального storage. Копия содержит закрытые документы, хеши паролей, `.env` и ключ расшифровки SMTP: храните весь набор с правами 0700/0600, на защищённом носителе. Контрольные суммы обнаруживают повреждения, но не заменяют подпись доверенного источника и шифрование носителя.

## Создание

Из существующего checkout на сервере с работающими PostgreSQL/Redis:

```bash
cd /opt/ventilyator
python3 infrastructure/scripts/backup.py
```

По умолчанию копии появляются в `.local/backups/ventilyator-<UTC>-<id>`. Для отдельного резервного диска:

```bash
python3 infrastructure/scripts/backup.py --output /путь/к/закрытому/backup
python3 infrastructure/scripts/backup.py --verify /путь/к/backup/ventilyator-UTC-id
```

Проверьте свободное место заранее. Скрипт останавливает работающие API/worker, выполняет pg_dump custom format, архивирует storage вместе с `.keys/mail.key`, сохраняет `.env` в `configuration.env`, manifest с Git revision, миграциями и SHA-256, проверяет архив и запускает **те же** контейнеры. На время операции веб-запись недоступна. Другие CLI-писатели в это время запускать нельзя; копирование/восстановление выполняйте последовательно.

Копия не включает Redis-сессии/кеш, Docker-образы, Git-игнорируемые Compose override и каталог DATA_ROOT/config с TLS-ключами/CA Caddy. Сохраните нужные server override и TLS-конфигурацию отдельной защищённой процедурой; для восстановления нужны совместимые исходники и образы. Незавершённая копия не имеет проверенного manifest и не пригодна для восстановления. Автоматического удаления старых копий нет.

## Восстановление только в отдельную пустую установку

1. Подготовьте другой сервер или изолированный Compose project с другим DATA_ROOT и портами. Установите совместимую версию из GitHub, создайте **новую** целевую `.env` через configure.py и каталоги через prepare-host.sh. Не создавайте администратора и не запускайте API до восстановления. Целевые пароли PostgreSQL/Redis могут отличаться от исходных.
2. Скопируйте полный проверенный backup в закрытый каталог целевого сервера. Установите необходимые Compose-профиль, сертификаты и origin целевой установки.
3. Соберите образы и запустите только зависимости:

```bash
cd /opt/ventilyator
docker compose build ventilyator-api ventilyator-web ventilyator-proxy
docker compose up -d --wait --wait-timeout 180 ventilyator-postgres ventilyator-redis
python3 infrastructure/scripts/restore.py /путь/к/backup/ventilyator-UTC-id
```

Последняя команда только проверяет набор и совместимость миграций. Применение:

```bash
python3 infrastructure/scripts/restore.py /путь/к/backup/ventilyator-UTC-id --apply-empty-target
docker compose up -d --no-build --wait --wait-timeout 180
docker compose ps -a
```

Скрипт отказывается перезаписывать организацию/пользователей или непустой storage, проверяет контрольные суммы и запрещает ссылки/небезопасные пути в tar. Дамп восстанавливается транзакционно, файлы — с владельцем приложения. Целевой `.env` сохраняется; `configuration.env` из копии автоматически не применяется. Redis целевой установки очищается; после восстановления войдите заново. Pending email из PostgreSQL восстанавливается worker.

Проверьте вход, существующую задачу/документ, скачивание и SHA-256 файла, SMTP-настройки с восстановленным ключом. При отказе после начала изменения данных скрипт оставляет писателей остановленными: сначала устраните причину. Это не автоматический rollback поверх работающей установки.

## Проверка реализации

`tests/integration/backup_restore.py` создаёт временные данные, делает согласованную копию, восстанавливает в отдельный Compose project с новым DATA_ROOT/портом и другими паролями PostgreSQL/Redis. Проверяет вход, задачу, страницу, точные байты вложения, расшифровку SMTP и отказ повторного восстановления поверх данных. Целевой проект удаляется; исходные пользовательские данные не удаляются. Реальное регулярное восстановление ваших копий на резервном Ubuntu остаётся эксплуатационной обязанностью.
