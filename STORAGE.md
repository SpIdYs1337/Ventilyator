# Локальное файловое хранилище

Содержимое хранится только на диске Ubuntu, без S3/MinIO. PostgreSQL хранит метаданные, версии, SHA-256, контекст task/page, квоты и журнал загрузок. Caddy не раздаёт storage напрямую.

API выдаёт билет для конкретной задачи/страницы; затем принимает поток PUT application/octet-stream. Проверяются права, размер 1–25 MiB, имя, свободное место, резервы и квота. Файл пишется с O_EXCL/O_NOFOLLOW, вычисляется SHA-256, определяется безопасный MIME, выполняется fsync и необязательная антивирусная проверка. Публикация версии проходит транзакционно после повторной проверки прав и билета. Общая длительность потока ограничена 120 секундами.

Физический путь задаётся сервером: `storage/objects/ab/cd/<uuid>/v0001.bin`. Пользовательское имя не становится путём. Родительские каталоги проверяются на символические ссылки, разделение организаций закреплено составными FK. Одновременные резервы квоты и общего физического места сериализуются advisory locks. Остаётся запас 100 MiB; квота по умолчанию 10 GiB на организацию. Квота учитывает все версии и корзину, освобождения места при простом перемещении в корзину нет.

Скачивание требует активной сессии и доступа к контексту при каждом запросе. Ответы — attachment/nosniff, размер и безопасное Content-Disposition. Только PNG/JPEG/GIF/WebP могут отображаться inline; SVG/HTML не выполняются как предпросмотр. Старая версия доступна по `?version=N`, текущее изображение — по `?inline=1`. Вставка изображения в страницу использует этот защищённый URL.

Через веб доступны новая версия, история и SHA-256, переименование, корзина/восстановление и квота организации. В «Администрирование → Хранилище» доступны состояние операций и сверка: до 100 просроченных/неуспешных операций за запуск, без удаления опубликованной версии. Список вложений сейчас показывает 200 последних объектов контекста; сервер ограничивает один объект 1000 попытками загрузки версий. Полная пагинация файлов остаётся в дорожной карте. Незавершённые резервы могут удерживать место до сверки.

Ключ SMTP хранится в `storage/.keys/mail.key`; его нельзя удалять при обслуживании файлов. Общая файловая библиотека/папки, произвольное прикрепление одного объекта к нескольким контекстам, фоновое сканирование целостности, окончательное удаление по retention и карантин пока не реализованы. Интеграция ClamAV описана в CONFIGURATION.md, резервная копия — BACKUP_RESTORE.md.
