# Ventilyator Local Storage

Физические файлы находятся исключительно на локальном диске Ubuntu. API получает bind mount `${DATA_ROOT}/storage:/app/storage`; frontend, web-сервер и Caddy его не получают. S3, MinIO и S3-совместимые SDK не используются.

На первом этапе создаются `objects`, `temporary`, `quarantine`, `previews`, `thumbnails` с ограниченными правами. При запуске проверяются canonical root и отсутствие символических ссылок. Readiness действительно создаёт, синхронизирует и удаляет уникальный служебный файл, затем проверяет доступное место.

В PostgreSQL заложены StorageObject и StorageObjectVersion с версиями и SHA-256. Полноценные загрузка, скачивание, ACL, квоты, карантин, типизация содержимого, потоковая обработка и восстановление незавершённых операций ещё не реализованы. Каталог не публикуется напрямую, публичного файлового API пока нет.

Планируемый путь объекта: `objects/ab/cd/<uuid>/v0001.bin`. Пользовательское имя никогда не участвует в физическом пути. Будущий upload сначала проверяет авторизацию, квоту и размер, пишет во временный файл, определяет тип, вычисляет SHA-256, выполняет обязательную антивирусную проверку при её включении, атомарно перемещает объект и завершает PostgreSQL-операцию. Нужен отдельный журнал состояния: файловая система и PostgreSQL не имеют общей транзакции.

При переносе диска остановите все пишущие процессы, перенесите root с правами и контрольными суммами, измените DATA_ROOT, проверьте монтирование и readiness. Процедура общего восстановления должна тестироваться вместе с БД.
