# Дорожная карта

Область работ сохраняется по `docs/requirements.md`. Ни один незавершённый этап не считается готовым к эксплуатации.

## Уточнение требований

- Локальные пользователи и создание через веб-панель администратора обязательны.
- IMAP-вход и уведомления обязательны к реализации как дополнительные включаемые возможности. Их отсутствие настройки не блокирует локальную авторизацию и основные модули.

## Этап 1 — инфраструктура (runtime и браузер проверены)

- [x] Monorepo, React/Vite, NestJS, Prisma schema, PostgreSQL, Redis и BullMQ worker.
- [x] Dockerfiles и Compose, локальные bind mounts, Caddy с внутренним/корпоративным TLS.
- [x] Health endpoints, storage root, первая версия SQL-миграции.
- [x] Сборка frontend, модульные тесты, lint, живые PostgreSQL/Redis, SQL-проверка миграции.
- [x] Prisma generate, migrate deploy и проверка schema drift: расхождений нет.
- [x] Сборка контейнеров, полный запуск, readiness, реальная BullMQ job и сохранность PostgreSQL/Redis/storage после пересоздания контейнеров.
- [x] HTTPS через Caddy: недоверенный CA отклоняется, доверенный CA и имя сервера проверяются.
- [x] Браузерные E2E через установленный Chromium: desktop и mobile.
- [ ] Приёмка на отдельном Ubuntu Server с корпоративным сертификатом.

## Дальнейшие этапы

3. Завершение проектов и задач: workflow, защищённые вложения, расширенные операции и поиск.
4. Пространства знаний, дерево, Tiptap, optimistic locking, версии, черновики и ACL.
5. **Дополнительные уведомления:** SMTP-настройки, проверка подключения, BullMQ с outbox/idempotency, email-шаблоны, центр уведомлений, подписки и журнал доставок. Без SMTP внутренние основные модули продолжают работать.
6. Спринты, Scrum, Gantt, календарь, roadmap и учёт времени.
7. Локальное совместное редактирование, упоминания, шаблоны и согласования.
8. Настраиваемый Dashboard на реальных данных, аналитика и безопасная автоматизация.
9. Полное администрирование storage/квот, согласованные backup/restore, мониторинг и эксплуатационные процедуры.
10. Production hardening: безопасность, нагрузка, отказоустойчивость, обновления, сохранность и восстановление.

## Точный порядок продолжения

1. Проверить обновление и рабочий проект на целевом Ubuntu по docs/projects-tasks.md. Существующие локальные пользователи сохраняются.
2. Завершить оставшиеся функции Identity, включая управление/связывание IMAP в UI и проверку на настоящем настроенном сервере, редактирование/блокировку пользователей, reset пароля и управление ролями.
3. Завершить этап 3, затем базу знаний и безопасные файловые вложения.
4. Реализовать обязательные дополнительные уведомления этапа 5: внутренний центр, SMTP и надёжную очередь. Отсутствие SMTP не должно блокировать проекты и локальный вход.
5. Продолжить планирование, совместную работу, аналитику, backup/restore и hardening.
6. После каждого этапа обновлять результаты проверок и changelog; не объявлять платформу готовой до выполнения полного задания. Загрузка Playwright CDN всё ещё возвращает 403, но тесты выполняются с установленным системным Chromium; это не блокирует текущую браузерную проверку.
