# Безопасность

Система находится в разработке и не прошла production-аудит.

## Реализованные механизмы

- Argon2id: локальные пароли не сохраняются в открытом виде; создание пользователя требует минимум 14 символов.
- Сессионный секрет — случайные 32 байта в HttpOnly cookie. В PostgreSQL и ключах Redis хранится только SHA-256 идентификатора; cookie-секрет не пишется в localStorage.
- Redis sliding expiration: 7 дней либо 30 с «Запомнить меня», ограничено абсолютным пределом. Повторная аутентификация создаёт новый секрет.
- Серверная проверка отзыва и активности пользователя при каждом защищённом запросе; до 10 сессий на пользователя с блокировкой конкурентного создания.
- CSRF: точный Origin плюс обязательный нестандартный заголовок для всех изменяющих запросов, включая login. CORS не включён. Cookie SameSite=Lax, Secure при HTTPS.
- Redis rate limiting по IP и хешу email, автоматическое истечение через 15 минут. В API доверен один reverse proxy; порт API наружу не опубликован.
- Административные запросы требуют разрешение и организацию из проверенной сессии. Делегировать отсутствующие разрешения нельзя.
- Аудит входов, известных неудачных входов, выхода, создания пользователей/ролей и отзыва сессий.
- Helmet и CSP в Caddy; приложение не использует CDN или внешние шрифты. Секреты исключены из Git и сборочного контекста.
- IMAP всегда implicit TLS с проверкой сертификата. Пароли почты используются только в запросе к ImapFlow; логирование библиотеки отключено.

## Дополнительно реализовано

- Объектные ACL проектов/пространств/файлов, составные организационные FK, защита поиска и отчётов от выдачи чужих объектов.
- Административное отключение/сброс пароля и смена ролей отзывают сессии. Самостоятельная смена пароля проверяет старый и завершает сессии. Нельзя отключить себя или делегировать отсутствующие права.
- Rich JSON проходит структурную проверку, исполняемые ссылки/внешние встроенные изображения/произвольные HTML-классы отклоняются. Файлы скачиваются с nosniff/attachment, безопасные растровые изображения могут быть inline.
- Загрузка ограничена размером, временем, квотой/физическими резервами, защищена от клиентских путей и symlink; необязательная обязательная проверка ClamAV отказывает при недоступном сканере.
- SMTP TLS/STARTTLS с проверкой CA/имени. Пароль AES-256-GCM, ключ вне БД в storage; расшифровка привязана к организации. Worker проверяет доступ ещё раз перед отправкой.
- IMAP не связывает локальный аккаунт по совпавшему email. Автосоздание проверяет непривилегированную роль при каждом создании.
- Backup валидирует SHA-256/архивные пути, запрещает ссылки/спецфайлы; restore отказывается перезаписывать существующих пользователей/организации/файлы.

## Ограничения и проверка перед эксплуатацией

Нет CRDT/WebSocket, расширенных page ACL, OAuth2/LDAP, production-аудита зависимостей и нагрузочной приёмки. Сессии содержат User-Agent как недоверенные метаданные; старые истекшие записи PostgreSQL пока не очищаются автоматически. SessionStorage содержит локальный черновик страницы до публикации; на общей рабочей станции закрывайте вкладки/профиль браузера.

Проверены межорганизационные запреты, CSRF, отказ повышения привилегий, конфликтующие записи, файл/черновики и локальные TLS SMTP/IMAP fixtures. Это не аудит вашей сети, корпоративной почты или установленного ClamAV. Нужны приёмка TLS/backup на целевом Ubuntu, анализ зависимостей и политика доступа к серверу/копиям. Ограничьте доступ к .env, ключам и Docker socket. HTTP LAN-профиль используйте только в изолированной тестовой сети; эксплуатационный профиль — HTTPS.

Backup включает .env, SMTP-ключ и закрытые данные; права 0700/0600 не заменяют шифрование резервного носителя. Контрольные суммы не подтверждают происхождение недоверенного архива. Полный перечень оставшихся работ — ROADMAP.md.
